# Feature Specification: Loan Lookup

**Feature Branch**: `002-loan-lookup`  
**Created**: 2026-05-11  
**Status**: Draft  
**Input**: User description: "Add the next loan-management workflow after create loan: look up one current loan by loan ID, leaving listing and deletion for later."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Retrieve a Current Loan (Priority: P1)

A caller can request one current loan by loan ID so they can confirm the details
of a loan that was created during the active application session.

**Why this priority**: Single-loan lookup is the next smallest useful workflow
after loan creation. It lets reviewers prove that accepted records can be
retrieved without introducing broader listing, deletion, persistence, or user
interface scope.

**Independent Test**: Create a valid loan, request the same loan ID, and confirm
the returned record matches the stored loan.

**Acceptance Scenarios**:

1. **Given** a loan exists for the supplied loan ID, **When** the caller requests that loan ID, **Then** the stored loan record is returned.
2. **Given** the supplied loan ID has leading or trailing whitespace, **When** the caller requests the loan, **Then** matching ignores the surrounding whitespace.
3. **Given** the supplied loan ID differs only by letter case from a stored loan ID, **When** the caller requests the loan, **Then** the system treats it as a different ID.

---

### User Story 2 - Explain Missing Lookup Results (Priority: P2)

A caller receives a clear response when no current loan exists for the requested
loan ID so they can distinguish an absent record from a system failure.

**Why this priority**: Clear not-found feedback is required for a lookup workflow
to be usable and testable, but it depends on the primary retrieval behaviour.

**Independent Test**: Request a loan ID that has not been created during the
current application session and confirm a clear not-found response is returned.

**Acceptance Scenarios**:

1. **Given** no current loan exists for the supplied loan ID, **When** the caller requests that loan ID, **Then** the system reports that no matching loan exists.
2. **Given** the application has restarted since a loan was created, **When** the caller requests the old loan ID, **Then** the system reports that no matching loan exists.

### Edge Cases

- Lookup loan ID is missing, blank, or whitespace-only.
- Lookup loan ID has leading or trailing whitespace.
- Lookup loan ID differs from a stored loan ID only by letter case.
- Lookup loan ID was valid in a previous application session but no longer
  exists after restart.
- Lookup is attempted before any loans have been created in the current session.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST allow callers to retrieve one current loan by loan ID.
- **FR-002**: System MUST trim surrounding whitespace from lookup loan IDs before matching.
- **FR-003**: System MUST match lookup loan IDs case-sensitively.
- **FR-004**: System MUST return the stored loan record when a current matching loan exists.
- **FR-005**: System MUST return a clear not-found message when no current matching loan exists.
- **FR-006**: System MUST keep lookup limited to one loan at a time; listing all loans is out of scope for this feature.
- **FR-007**: System MUST retain the existing temporary-session storage boundary; lookup must not imply persistence after restart.
- **FR-008**: System MUST provide clear setup, run, test, and demo instructions for the lookup workflow.
- **FR-009**: System MUST be testable with automated coverage at or above 80%.

### Key Entities *(include if feature involves data)*

- **Loan**: A temporary record representing one loan during the current
  application session. Key attributes are loan ID, borrower name, funding
  amount, and repayment amount.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: A reviewer can create a loan and retrieve it by loan ID within 3 minutes after the application is running.
- **SC-002**: A lookup for an existing loan returns the stored record within 2 seconds in local test usage.
- **SC-003**: A lookup for an unknown or expired loan ID returns clear feedback within 2 seconds in local test usage.
- **SC-004**: Case-sensitive and whitespace-trimmed lookup behaviour is covered by automated tests.
- **SC-005**: Reviewer can run the application and test suite from documentation without missing setup steps.
- **SC-006**: Test command reports at least 80% statement coverage.

## Assumptions

- Loan creation already exists and remains the way current loans enter the system.
- Loan IDs are caller-supplied and are not generated by the system.
- Loan ID matching follows the existing create-loan rule: trim surrounding whitespace and preserve case-sensitive identity.
- Current loans remain temporary and disappear when the application process restarts.
- Browser UI, loan listing, loan deletion, authentication, public exposure, and cloud-hosted deployment are out of scope for this feature.
- The solution must remain explainable in under 40 minutes.
